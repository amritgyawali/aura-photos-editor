# ADR-0133: Material lab, selection authoring and photo inspection

Date: 2026-10-20. Continues ADR-0132 in response to another request for fifty additional capabilities.

Implement fifteen selection-bound material operations, fifteen mask authoring/topology workflows, and twenty read-only diagnostic outputs. Count complete operations; do not count individual sliders, channels, panels, resets, or operation ordering as additional capabilities. Distinguish independently implemented documented categories from original AURA extensions. REA metadata and bounded instruction/string references establish only the observations stated in the evidence report. They do not establish proprietary model recovery, complete application reconstruction, identical output, or superior photographic quality.

The validated `material_lab_v1` extension stores at most 32 explicit operations, each bound to an existing authored mask. Old recipes have no material processing. Shared kernels use selected-only sample weights; zero strength, disabled operations and unavailable masks are neutral. Mask opacity scales the result. Independent fine/coarse fabric gains share a frequency decomposition; this is an additional control mechanism, not an invention of frequency separation. Silver hair processing is a brightness/chroma heuristic inside the photographer's selection, not trained strand detection. Every material adjustment is opt-in and must be reviewed.

Material operations run after extended local colour and before output sharpening/geometry. Both previews and exports use the native pipeline. Full-frame rendering avoids filter seams, render hashes include the extension, and pre-retouch checkpoints exclude this later stage. Colour-only comparison omits material corrections. Saving uses membership and revision checks, the user merge and one atomic history step. Complete stack replacement removes deleted entries. Existing recipe/version contracts remain unchanged; no migration, third-party weights, assets, or additional network dependency is introduced.

Mask component geometry edits preserve vector/brush data. Topology and composed placement freeze coverage through the existing bounded grid and matte encoding, with explicit source-coordinate limits. Existing settings, unrelated masks, local colour and exact Undo/Redo are preserved. The existing mask command supports the new typed actions, avoiding duplicate IPC infrastructure.

Photo inspection renders the current saved edit at a maximum 512-pixel edge. Twenty distinct bounded diagnostics expose scopes, spatial maps, colour/tone distributions, and artifact/detail indicators. Membership/revision are checked before and after processing. Inspection does not save edits; results and late responses are invalidated on navigation/revision changes. Pixel-scale patterns are preview measurements, and scene structure may contribute to apparent noise/banding/alignment. They are not native sensor measurements or proofs of a defect.

Validation covers arithmetic effects, neutral defaults, determinism, excluded pixels and kernel inputs, bounded data, persisted settings, history, stale writes, original bytes, UI drafts, native command registration and production builds. Real portrait cohorts, three-machine performance and paired Evoto exports remain separate acceptance work; passing synthetic mechanics is not photographic qualification.
